## 改三个 GitHub Actions workflow

### 修复 1：缓存 ffmpeg 下载（ci.yml + package_gui.yml + release.yml）

三个 workflow 都有相同的 "Fetch ffmpeg from upstream release" 步骤，每次重新下载 ~100MB zip。改成用 `actions/cache` 缓存解压后的目录。

**做法**：在每个 workflow 的 ffmpeg 下载步骤前，加一个 cache 步骤：
```yaml
- name: Cache ffmpeg upstream bundle
  id: cache-ffmpeg
  uses: actions/cache@v4
  with:
    path: upstream-bundle
    key: ffmpeg-upstream-3.0.2

- name: Fetch ffmpeg from upstream release
  if: steps.cache-ffmpeg.outputs.cache-hit != 'true'
  shell: pwsh
  ...（原有下载逻辑不变，加 if 条件跳过缓存命中时）
```

缓存 key 用固定值 `ffmpeg-upstream-3.0.2`，因为上游版本固定不变。一旦命中缓存就跳过下载。

### 修复 2：Release workflow 补 portable 产物（release.yml）

`release.yml` 目前只用 `tauri-action` 上传 NSIS installer，没有 portable 目录。把 `package_gui.yml` 里的 "Prepare portable folder" 步骤复制到 `release.yml`，放在 `tauri-action` 之后，然后把 portable 目录上传为 Release asset。

**做法**：在 release.yml 的 `tauri-action` 步骤后新增：
1. "Prepare portable folder" 步骤（从 package_gui.yml 原样复制）
2. 用 `gh release upload` 把 portable 目录打成 zip 上传到 Release：
```yaml
- name: Upload portable zip to release
  shell: pwsh
  env:
    GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
  run: |
    Compress-Archive -Path .portable-dist/m3u8-queue-downloader-portable/* -DestinationPath portable.zip
    gh release upload app-v${{ ... }} portable.zip
```

注意：版本号来自 tauri.conf.json，tauri-action 已经用它创建了 tag。这里直接用 `${{ github.ref_name }}` 作为 release tag（因为 tag push 触发时 ref_name 就是 tag 名）。

### 修复 4：prerelease 标记 bug（release.yml 第 100 行）

根因：`contains(github.ref_name, '-')` 检查的是整个 tag 名 `app-v0.2.0`，但 `app-v` 前缀自带连字符，导致永远为 true。

修法：改成只检查版本号部分有没有 pre-release 标识。用 `github.ref_name` 去掉 `app-v` 前缀后再检查：
```yaml
prerelease: ${{ github.event_name == 'workflow_dispatch' && inputs.prerelease || contains(github.ref_name, 'app-v') && contains(slice(github.ref_name, 5), '-') }}
```

但 GitHub Actions 不支持 `slice()`。更简单的写法：用正则匹配版本号中的 `-`：
```yaml
prerelease: ${{ github.event_name == 'workflow_dispatch' && inputs.prerelease || contains(github.ref_name, '-rc') || contains(github.ref_name, '-beta') || contains(github.ref_name, '-alpha') }}
```

这样只有版本号含 `-rc`/`-beta`/`-alpha` 时才标为 prerelease，正常的 `app-v0.2.0` 不会误标。
